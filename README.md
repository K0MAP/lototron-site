# Лототрон (lototron-site)

**Лототрон** — статичний однофайловий веб-застосунок для розіграшей з учеть Twitch-чату:
**колесо фортуни** (ручний набір учасників із квитками) і **рухома стрічка** (учасники з прямого
Twitch-чату). Підходить для стрімерів, модераторів та будь-яких онлайн-розіграшів.

## Опис

Застосунок представляє себе як одну сторінку `index.html` з вбудованими CSS і JavaScript —
без backend-сервера, без установки, без спотворень. Всі дані зберігаються локально в
браузері (localStorage/IndexedDB), експортуються та імпортуются у вигляді файлів JSON.

## Особливості (деталі)

### Режими розіграшу
- **Колесо фортуни** — ручний список учасників, кожен з квитками (`Ім'я;квитки`).
  Колесо має рівно по 1 слоту на квиток, переможець обирається по повному пулу квитків.
- **Рухома стрічка** — учасники додаються з Twitch-чату каналу:
  - участь за будь-яким повідомленням або за ключовим словом (за замовчуванням `!join`);
  - автоматично визначаються роли: підписник, VIP, модератор, артист, стрімер, чат-бот;
  - множник квитків для кожної ролі (або один спільний для всіх);
  - перевірка активності переможця в чаті з таймером (0–3600 с) і можливістю реролу.

### Гравча логіка
- 1 квиток = 1 рівної ширини слот; розіграш ведеться по всім квиткам, візуальне колесо
  обмежено 400 слотами (reservoir sampling) — шанси всіх квитків залишаються рівними.
- Ненаправлений RNG на основі `crypto.getRandomValues` (реджекшн-метод для безсторонності).
- Режим вибування: випавши квиток вибуває, розіграш триває, доки не залишиться зазначена
  кількість останніх квитків — їхні власники стають переможцями. Авто-спіни доступні
  лише в цьому режимі.
- Пауза, скасування останнього спіну, перемішування перед кожним прокрутом.

### Налаштування
- Швидкість обертання (0,25×–8×), тема: **темна (HUD)**, **світла (індустріальна)**,
  **нічна**, **власна** (кастомна палітра з інтерактивним питанням); скруглення.
- Звук (WebAudio, квадратна складка) з гучністю; анімації, конфетти, ефект віддачі.
- Заглушка центру колеса (зірка/монета/серце/череп/самоцвіт) або своє зображення
  (GIF/PNG/WebP/JPEG до 5 МБ) із вмотивом обертання.
- Сортування та пошук у списку учасників; інлайн-редагування кількості квитків
  (підтримка `+N` для додавання); відсотки шансу перемоги біля кожного імені.

### Керування шоу
- ** Live-табло результату** на сцені: під час обертання — «дешифрований» телетайп
  поточного сектора, по перемозі — ім'я з шансом у відсотках.
- **Команди з Twitch-чату** (для стрімера та модераторів, по бейджів у IRC-тегах,
  без реєстрації): `!spin` / `!крути`, `!open`, `!close`, `!reroll` / `!рерол`.
- **Режим OBS-overlay** — кнопка або клавіша `F` (або `?obs=1` у URL): сцена на весь
  екран з прозорим фоном, без панелей управління.
- **Подіум останніх переможців** під стрічкою; вкладки «Учасники / Вибування / Історія»
  у сайдбару; «липка» сцена при скролі.

### Соціальні механізми
- **Картка переможця** (📸): генеруюча canvas-картинка з аватаром, шансом і водяним
  знаком «CSPRNG Fair Play» — копіюється у буфер обміну (з альтернативою скачування).
- **Поділитися колесом** (🔗): колесо кодується в `#wheel=...` посилання — хто відкриє
  посилання, отримає готовий список учасників.
- Бейдж **🛡️ CSPRNG Fair Play** — візуальний аргумент чесності розіграшу.

### Дані
- Експорт усіх даних у `lototron.json` (налаштування, учасники, гісторя переможців,
  список забанених) і переможців у CSV.
- Імпорт JSON із валідацією та бранюванням усіх значень.
- Інтегроване сповіщення, якщо збереження в localStorage не вдалося (заповнення сховища).

## Вимогови
- Сучасний браузер (WebSocket, `crypto`, CSS-змінні, `color-mix`, `<dialog>`).
- Режим «Рухома стрічка» потребує доступу до інтернету (Twitch IRC + decapi.me);
  режим «Колесо фортуни» працює повністю офлайн.

## Запуск

Сторінка статична — відкрийте `index.html` у браузері або розгорніть через будь-який
статичний хостинг:

```bash
# локально (необхідно, щоб work з файлом без file:// обмежень)
npx serve .
# або
python3 -m http.server 8000
```

**Deploy:** репозиторій підходить для GitHub Pages, Netlify, Vercel або будь-якого
статичного хостингу — без налаштування чи серверних скриптів.

## Структура репозиторію

```
index.html                      главна сторінка (HTML + CSS + JS, єдиний файл застосунку)
README.md                       опис проєкту (цей файл)
docs/TECHNICAL.md               технічна документація (ТД): архітектура, структура даних,
                                безпека, алгоритми, збереження, відновлення
backup/                         додатково збережений бекап попередньої версії
  index-b9c226c2-previous.html      index.html версії b9c226c2 (локальний бекап)
```

## Документація

- **Опис і інструкції** — цей `README.md`.
- **Технічна документація** — [docs/TECHNICAL.md](docs/TECHNICAL.md): архітектура, моделі даних,
  ключі сховищ, алгоритми розіграшу, протоколи безпеки, обмеження, посібник з deploy
  та відновлення попередньої версії.

## Відновлення попередньої версії

Попередня версія `index.html` зіхранена в комітній історії (коміт `b9c226c`):

```bash
git show HEAD~1:index.html > index.html
```

Також є локальний бекап: `backup/index-b9c226c2-previous.html`.
