# Технічна документація (ТД) — Лототрон

Дані документації описують архітектуру, моделі даних, алгоритми, безпеку та інструкції
розгортання і відновлення для проєкту `lototron-site`.

## 1. Обзор та архітектура

Застосунок — **однофайловий статичний веб-сайт**: усі HTML, CSS і JavaScript лежать у
`index.html`. Немає backend-сервера, БД чи зовнішніх скриптів. Інтерфейс і логіка
зберігаються у власному налаштуванні:

```
index.html  (один файл застосунку)
  ├─ <style>      усі стилі (теми, розкладка, анімації)
  └─ <script>     уся логіка (один анонімний блок, без модулів)
```

**Зовнішні залежності** (дозволені через CSP):

| Прогноз | Використання |
|---|---|
| `wss://irc-ws.chat.twitch.tv:443` | WebSocket до Twitch IRC (чат каналу) |
| `https://decapi.me` | avatar і follow-статусу учасників |
| `https://static-cdn.jtvnw.net` | аватарки та badge Twitch |
| `https://fonts.googleapis.com`, `fonts.gstatic.com` | шрифт Press Start 2P |

## 2. Модель даних

### 2.1 Структури

**wheel (колесо)** — ручний список учасників:
```json
{ "n": "Ім'я", "t": 3, "o": 5, "lt": 1690000000000 }
// n — ім'я (до 40 знаків), t — квитків зараз (0..1000),
// o — початково квитків, lt — час останнього вибування
```

**tape (стрічка)** — учасники з Twitch:
```json
{ "n": "Ім'я", "login": "login", "id": "user-id", "recent": [{"t":1,"x":"…"}],
  "badges": ["sub","mod"], "av": "https://static-cdn.jtvnw.net/…",
  "sub":1, "vip":0, "mod":0, "artist":0, "owner":0, "bot":0, "fol": true }
```

**hist (гісторя переможців)** — per mode:
```json
{ "n": "Ім'я", "t": 1690000000000, "fin": 1, "login": "…", "state": "wait|ok|late",
  "sec": 60, "dl": 1690000060000, "rt": 1690000055000, "msgs": [{"t":1,"x":"…","pre":1}] }
```

**Стан розіграшу** (`st`): speed, theme, custom, cgSpr, spinMode, roles, reply, mx/mxAll/mxG,
rm, keepN, shuf, vol, snd, resetT, m.

### 2.2 Сховища

| Сховище | Ключ(и) | Значення |
|---|---|---|
| localStorage | `lt_set` | усе налаштування (sanitized через `fix()`) |
| localStorage | `lt_m` | поточний режим: `wheel`/`tape` |
| localStorage | `lt_wheel`, `lt_tape` | учасники (обмеження: 5000 / останні 500) |
| localStorage | `lt_wh`, `lt_th` | гісторя переможців (100) |
| localStorage | `lt_ban` | забанені імена (до 5000) |
| localStorage | `lt_tw` | попередні введення channel/keyword/any |
| localStorage | `lt_cgr` | вмотив обертання центру |
| localStorage | `lt_cg` | legacy-ключ зображення центру (міграція в IndexedDB) |
| IndexedDB | `lototron` v1, object store `kv`, ключ `cg` | blob зображення центру колеса |

Збереження: дебонс 300 мс (`save()`), злиття при `pagehide` (`flushSave()`).
Помилка сховища виводиться під низом сторінки з кнопкою «Спробувати ще».

## 3. Алгоритми розіграшу

### 3.1 Случайність
- `rnd()` — 53-бітна дробова числа з `crypto.getRandomValues`.
- `randInt(n)` — **реджекшн-метод** (`x < floor(2^32/n)*n`) для несвійствованості.
- `shuffle()` — алгоритм Фішера–Йєтса на `randInt`.

### 3.2 Пуло квитків і візуальне колесо
- 1 квиток = 1 слот рівної ширини.
- `slotsOf()` — побудова слотів для візуалізації; **reservoir sampling** обмежує
  візуальне колесо 400 слотами, але до розіграшу долучаються **всі квитки пула** —
  шанси рівні.
- `pad()` — повторення учасників до мінімуму 12 слотiв (порожнє колесо = 12 «заглушек»).
- `spin()` — вибір переможця за індексом у повному пулі квитків; щоб переможець
  попав в точку приземлення, його слот вставляється в `ring` перед обертанням.
- Обертання: зсув `pos` з ease-out (`1-(1-k)^4`), дві петлі (колесо/стрічка),
  ідлій дрейф при нульовому значенні.

### 3.3 Вибування (elimination) і авто-спіни
- `elim()` = `st.rm && st.m==='wheel'`. Після випадання квитка його власник вибуває
  (`t -= 1`, запис у вибування); якщо залишилось `<= keepN` квитків — фінішується.
- `resetT` — пороговий час: фінали, старіші його, не враховуються в `wonAll()`;
  скидається при «Скинути вибування» і «Очистити».
- Авто-режим лише для вибування; таймер повторного спіну 650–850 мс, чекає закриття
  діалога переможця і паузи.
- `undo()` — скасування останнього спіну (повертає квиток або розбаничує ім'я).

### 3.4 Ролі та множники (режим стрічки)
- Ролі: viewer, sub, vip, mod, artist, follow, nofollow, bot, owner.
- `can(u, A)` — визначення eligibility за відмітками ролі та follow-статусом.
- `tix(u)` — множник квитків: загальний (`mxAll`/`mxG`) або найбільший по росям
  (включаючи follow/nofollow/bot/owner).
- Follow-статуси качуються з decapi.me з таймаутом 6 с, перезавантаження з поверненням
  у чергу (до 3 виступа, після чого `fol=null` — учасник без ролі follow/nofollow).
- Повідомлення дедублікуються за `msg-id` (cap 300).

### 3.5 IRC-з'єднання
- Анонімний ніке `justinfan` + рандомни PIN 10000–90000, `CAP REQ :twitch.tv/tags
  twitch.tv/commands`, `JOIN #<channel>`.
- Підтримка PING/PONG, авто-перепідключення з експонентою затримкою (max 15 с),
  heartbeat: закриття socket, якщо 36 с не було повідомлень.

## 4. Безпека

- **CSP** (`<meta http-equiv>`): `default-src 'none'`, `script-src 'unsafe-inline'`,
  `style-src 'unsafe-inline' https://fonts.googleapis.com`, `img-src data: blob:
  https://static-cdn.jtvnw.net`, `connect-src wss://irc-ws.chat.twitch.tv
  https://decapi.me`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`,
  `upgrade-insecure-requests`.
- **Немає `innerHTML`** — DOM ведеться через `el()`/`textContent`, що виключає DOM-XSS.
- Відповіді Twitch/decapi обгортуються **валідацією regex** до використання
  (URL аватара — лише `static-cdn.jtvnw.net`, followage — формат тексту).
- **Інпут-гігієна**: всі дані з localStorage/імпорту проходять `cleanWheel/cleanTape/
  cleanHist` (довжина, валідація login, фільтрація badge, обмеження квитків).
- **Імпорт** JSON валідний (`v=1`, типи поля, структура) і проходить `fix()`;
  ключ `lt_ban` обмежено 5000 рядками.
- **CSV-експорт** захищений від інжекції формул (ескейп `= + - @` та дублява можливих).
- Користувачькі зображення центру колеса (SVG/GIF/…) відображаються через `<img>`
  — SVG-файл у `<img>` є ізольований і не виконує скрипти.
- Ключові заходи: `referrer no-referrer`, заборона об'єктів та форму, вимикає
  візуальне вказівник збройних змінних.

## 5. Продуктивність та обмеження

| Об'єкт | Обмеження |
|---|---|
| Візуальних слотів колеса | 400 (reservoir) |
| Учасників колеса | 5000 |
| Учасників стрічки | останні 500 |
| Зображень у списку/вибуванні | 300 |
| Повідомлень у чаті | 40 |
| Записів гістори | 100 (збереження) / 150 ( memory) |
| Скасувань | 50 |
| Збереження | дебонс 300 мс; flush при pagehide |

- Одина `requestAnimationFrame`-петля для всіх анімацій.
- FLIP-анімації списків лише до 150 елементів.
- Увага до `prefers-reduced-motion` (масштаб анімацій/звуку).

## 6. Доступність (a11y)

Скіп-лінк, aria-label/aria-pressed/aria-live (`#announce`), `<dialog>` для діалогів,
`focus-visible`, контрастні теми, об'ємні зоне 44×44 пк (`@media pointer:coarse`),
tab'snumeric вигляд чисел, апострофи звуком.

## 7. Експорт / імпорт

- **Експорт** `lototron.json`:
  `{ v: 1, set: {speed, theme, custom, cgSpr, spinMode, roles, reply, mx, mxAll, mxG,
  rm, keepN, shuf, vol, snd, resetT}, wheel, tape, hist, ban }`.
- **Імпорт**: валідація типу, `clean*`-бранювання, відновлення налаштувань через
  `fix()`, повідомлення про помилку при некоректному файлі.
- **CSV-експорт переможців** — UTF-8 з BOM, коректний escaping.
- Зображення центру колеса (blob у IndexedDB) не експортується — переноситься
  лише на тому ж браузері/пристрої.

## 8. Розгортання

Станційно статична: GitHub Pages, Netlify, Vercel або будь-який статичний хостинг.
Немає серверних скриптів, конфігураційних файлів або залежностей для інсталяції.

## 9. Відновлення попередньої версії

```bash
git show HEAD~1:index.html > index.html
```

Локальний бекап: `backup/index-b9c226c2-previous.html` (версія `b9c226c2`).
Гіт-історія також містить усі попередні версії `main`.
